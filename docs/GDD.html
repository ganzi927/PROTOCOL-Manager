01. 검토 결론과 확장 방향

이 기획은 소재와 시스템 목록은 충분하지만, 아직 구현자가 동일한 결과를 만들 수 있는 규칙 명세는 아니다. 가장 먼저 보강할 부분은 기능 추가가 아니라 판정의 완결성, 의사결정의 효과, 장기 경제, 저장과 재개다. 이 확장본은 원안의 텍스트 중계·5인 팀·육성·밴픽·장기 커리어를 유지하면서 실행 가능한 기본안을 제시한다.

문서 상태: 검토용 통합 설계안 v2.0 / 2026-09-09. 새 수치는 검증 전 초기 튜닝값이며 실제 e스포츠 통계가 아니다. 사용자에게 아직 확인받지 않은 제품 선택은 권고 기본값으로 표시한다. “완벽함”은 모든 기능을 넣는 것이 아니라 규칙의 빈틈을 닫고, 반복 시뮬레이션과 플레이테스트로 확인하는 것으로 정의한다.

유지할 강점발전 방향
팀·선수 ID와 표시 자산 분리규칙·시드·표시팩 버전까지 분리해 기존 세이브 보호

04. 규칙팩·캘린더·대회

대체자가 없으면 공용 긴급 선수 풀에서 해당 포지션 능력 35인 선수를 경기당 0.02억으로 임시 계약할 수 있다. 정식 계약·시즌캡 대상은 아니며 매치 종료 시 소멸, POG·경기 기록은 남는다. 장기 로스터 구축에는 비효율적인 낮은 능력으로 설계한다. 사용자가 이를 거절하면 매치 전체 0:2 또는 0:3 몰수패, 선수 기록 생성 없음. 정규 등록일에 포지션 5개가 비면 진행을 막고 해결 버튼을 제시한다. AI에도 동일 규칙 적용.

매치 잠금 동안 방출·영입·재계약 변경은 다음 매치부터 적용한다. 선수가 다른 팀과 동시에 계약하거나 한 세트에 두 슬롯으로 출전하는 데이터는 저장 자체를 거부한다.

09. 경기 엔진 — 원인에서 결과로

3페이즈 투표를 제거하고 자원 우위가 누적되는 8개 이벤트 모델로 대체한다. 이 엔진은 LoL 전체 물리·경제를 재현하지 않는 추상 시뮬레이션이다. 골드·킬을 실제처럼 임의 생성하지 않고, 정규화된 우위 G와 압박점수로 상태를 표현한다. 따라서 중계에 실제 게임 시간을 단정하거나 존재하지 않는 바론 스틸을 꾸며 넣지 않는다.

원안의 4표 방식에서 각 페이즈가 독립 50%라면 동률은 25%다. “후반 우선”으로 풀면 초반 2개를 이긴 팀도 후반을 지면 항상 패하므로 초반의 의미가 사라진다. 누적 우위 모델은 이 구조적 문제를 해결하기 위한 변경이다.

세트 컨디션, 드래프트, 결과, 서사 문구는 서로 다른 난수 스트림을 사용한다. 난수는 OS 시간이나 UI 재생 속도로 만들지 않는다. 고정 PRNG 알고리즘·버전, seed, streamKey, eventIndex를 기록하며 서버 구현 한 곳에서만 판정한다.

POG는 승리팀의 실제 이벤트 기여로 정한다. 라인은 승리 라인 선수에게 2점(BOT은 ADC1.3/SUP0.7), 목표는 승리팀에 역할 가중치×2, 교전은 역할 가중치×3 분배. 승리팀 최고 누적점, 동점은 세트 고정 시드. 이 점수는 추상 기여도이며 실제 KDA·딜량이라고 표시하지 않는다.

12. 장기 커리어·신인·이벤트

원안의 무은퇴는 샌드박스 설정으로 보존한다. 기본 커리어에서는 처음부터 가상 신인이 들어오며 레전드 소진을 기다리지 않는다. 레전드 컴백은 별도 판타지 옵션이고 MVP에서는 제외한다. 과거 생년을 루키 나이로 덮어쓰지 않고 표시 나이와 커리어 성장 나이를 분리한다.

이벤트는 주간 결산 15% 확률로 최대1건. 동일 종류 쿨다운4주, 부정 이벤트는 팀당 연속 주 금지. 후보가 없으면 미발생, 재추첨 루프 없음. 팬미팅은 다음 주 선택: 참가하면 해당 선수 훈련 대신 FORM+8/BURN−4, 거절하면 효과 없음. 인터뷰는 F+2. 부진 보도는 F−2까지이며 BURN을 다시 가산하지 않아 연패 악순환을 줄인다. 스폰서 이벤트는 현금+0.2억, 캡은 그대로다.

기대순위는 시즌 시작 당시 로스터의 공개 OVR 순위로 고정한다. 실제 시즌 종료 순위에서 다음 시즌 기대치를 갱신하므로 영원히 하위팀 기대치로 높은 만족도를 얻지 않는다. 난이도는 팀 선택과 정보·위임 수준으로 조절하고 AI에 숨은 능력 버프를 주지 않는다.

전체 오프라인 대안필수 요구가 되면 TS 단일 로컬 엔진+로컬 DB+세이브 분기 동기화로 재설계. C#과 TS 경기식을 중복 작성하지 않음

기존 문서가 “지금 쓰는 FSD·ASP.NET 지침”을 가정하지만 실제 코드베이스는 제공되지 않았다. 따라서 재사용 가능성을 확정하지 않고 기술 제안으로 유지한다. C# 엔진을 공유 API에서 실행하면 웹/모바일의 수치 불일치를 줄일 수 있으나 서버 운영이 필요하다.

POST /careers/{id}/commands
{
  commandId: UUID,
  expectedRevision: 42,
  type: "ResolveSet",
  payload: {matchId:"m_001", setIndex:2}
}
성공: {revision:43, resultId:"set_002", nextState:"RECAP"}
같은 commandId+동일 본문 재시도: 기존 응답 반환, 추가 계산/지급 없음
같은 commandId+다른 본문: 409 COMMAND_ID_REUSED
낮은 expectedRevision: 409 STALE_REVISION, 최신 상태 재조회
서버 검증 실패: 422 + 구체적인 해결 가능한 오류 코드

처리 순서: 소유권 확인→commandId 기존 영수증 확인→revision 조건부 갱신→합법 상태 검증→계산→새 스냅샷·이벤트·영수증 저장→커밋. commandId 및 setId 유니크 제약을 둔다. “진행” 버튼 이중 클릭 방지는 UX 보조이며 서버가 최종 보장한다.

PC와 휴대폰이 동시에 같은 세이브를 열면 먼저 커밋한 명령만 성공한다. 다른 기기는 새 revision을 받고 편집안을 다시 적용한다. 두 커리어 상태를 필드별 자동 병합하지 않는다. 네트워크 타임아웃 때는 같은 commandId로 재조회·재시도하며 새 seed를 만들지 않는다.

세트 결과는 계산 후 즉시 저장되므로 재접속하면 결과·리캡으로 복구한다. 로그 재생 위치는 편의정보로 별도 저장하며 손실되어도 결과 재생 또는 즉시 리캡 이동이 가능하다. 프론트에 “최근 저장 완료” 시간을 표시하되 클릭만으로 저장됐다고 표시하지 않는다.

보안 범위: 계정 소유권 검증, 웹 세션 쿠키의 HttpOnly/Secure 및 CSRF 방어, 앱 토큰은 OS 보안 저장소, 입력 크기 제한, API rate limit, 로그에 인증정보 제외. 클라이언트가 능력·승자·현금을 직접 쓰는 API는 만들지 않는다. 싱글 샌드박스 편집은 별도 명령으로 허용하고 경쟁 기록과 분리한다.

19. IP·현실 재현·남은 제품 결정

원안의 “개인 소장·비공개·비상업이면 실명·실제 로고 사용”은 허용을 보장하는 근거가 아니다. Riot의 공식 정책은 게임·앱에서의 IP 이용을 제한하고 로고·상표 사용에도 서면 라이선스 조건을 명시한다.[S2] API 키 보유를 이 매니지먼트 게임 전체의 허가로 해석하지 않는다. 팀·선수·사진 등 별도 권리도 Riot 정책 하나로 정리되지 않는다.

실제 제작은 가상 팀·선수·캐릭터·독자 아이콘 개발팩으로 진행할 수 있다. 실명 모드를 원하면 사용하려는 이름·사진·로고·대회·캐릭터 자산별로 권리자/허용 범위/근거를 기록하고 필요한 허가를 확보한다. 표시 이름만 바꾸고 기존 챔피언 아이콘·외형·설정을 그대로 사용하는 것을 완전 가상화로 보지 않는다. 문서 제목은 원안 식별용이며 정식 출시명은 별도 결정한다.

9.2
코어 알고리즘
한 세트를 3개 페이즈로 나눕니다. 각 페이즈마다 두 팀의 "페이즈 파워"를 계산하고, Elo 레이팅과 동일한 로지스틱 함수로 승률을 구해 그 확률대로 페이즈 승자를 뽑습니다.
// 0) 매치데이 컨디션 — 세트 시작 시 선수마다 1회 롤, 그 세트에서만 적용되는 휘발성 값(누적 없음)
condition_i = uniform(−3, +3)
// 1) 선수 스탯 항 — §9.3 표의 개인 스탯 가중치(w_stat)로 5인 평균, 컨디션 롤 반영
playerTerm(team, phase) = Σ( (stat_i + condition_i) × w_stat,phase ) / 5,  i = 1..5
// 2) 시너지 항 — 팀/듀오 게이지(§4.2)를 §9.3 표의 시너지 가중치(w_syn)로 반영
//    두 항의 가중치는 항상 합계 100%가 되도록 §9.3에서 맞춰둠(선수 항 + 시너지 항)
synergyTerm(team, phase) = Σ( synergy_gauge × w_syn,phase )
raw(team, phase) = playerTerm + synergyTerm
// 3) FORM 보정 — 50을 기준으로 한 편차를 ±10% 배율로 환산
formMult(team) = 1 + ( avg(FORM_i) − 50 ) / 50 × 0.10
// 4) BURN 페널티 — 한타 페이즈에서만, 평균 번아웃 10당 −1
burnoutPenalty(phase) = (phase == 한타) ? avg(BURN_i) / 10 : 0
P(team, phase) = raw(team, phase) × formMult(team) − burnoutPenalty(phase)
// 승률은 Elo식 로지스틱 — 점수차가 클수록 승률 격차가 커짐
p(A 승) = 1 / ( 1 + 10^( −(P_A − P_B) / S ) )

winner(phase) = weightedRandom(A: p, B: 1−p)

23. 해설 중계와 글로벌 골드 그래프

해설형 중계. 세트당 9개 이벤트의 한 줄 정형문을 캐스터 서술로 교체한다(narrate(), 전용 flavor rng로 승부 스트림과 분리해 결정론 유지). 라인전은 약 62% 확률로 킬 서술(“바텀에서 케이틀린이 룰루와 함께 상대 바루스를 잡아냅니다. 퍼스트 블러드!!” — 승리 라인 챔피언 + 무작위 조력 챔피언 + 상대 라인 챔피언, 첫 킬에 퍼스트 블러드), 나머지는 CS·주도권 서술. 오브젝트는 시야 장악 + 전령/드래곤(속성 랜덤) 확보, 가끔 처치 곁들임. 한타는 이니시 적중 + “n:k 교전 승리”, 기지 결전은 세트 마무리. 한국어 조사(을/를·이/가·은/는·와/과)는 받침 유무로 자동 선택. 구간마다 템플릿 2~3종.

글로벌 골드 그래프. 각 GameEvent에 팀 누적 골드 goldA/goldB를 추가한다. 양 팀 2500에서 시작해 이벤트마다 승자 이득(라인 ~340+ / 오브젝트 ~880+ / 한타 ~1600+ / 기지 ~2600) + 양측 패시브 ~540, 패자는 승자 이득의 34%(10단위 반올림). 리캡 화면은 이벤트 공개(reveal)에 맞춰 자라는 인라인 SVG 영역 그래프로 0선 기준 골드 차를 그린다(우세 = 라임 위, 열세 = 레드 아래). 헤드라인 “골드 차 +N.Nk”와 한 줄 코멘트로 어느 팀이 승리에 가까운지 즉시 보여준다.
