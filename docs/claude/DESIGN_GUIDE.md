# 디자인 가이드

## 제품의 화면 목표
구단 운영과 경기 결정을 바로 할 수 있는 한국어 게임 화면을 만든다. 기존의 짙은 차콜 배경, 라임색 주요 행동, 숫자가 잘 읽히는 스포츠 대시보드 구성을 이어간다. 랜딩 페이지나 광고성 히어로 화면으로 바꾸지 않는다.

## 실제 소스 기준 토큰
`app/globals.css`의 `:root, .dark` 및 후속 CSS가 근거다.

| 역할 | 현재 기준 |

| 기본 배경 | #101215 |
| 기본 글자 | #edf0ed |
| 카드 토큰 | #191c20 (일부 .panel은 #191d21) |
| 주요 버튼/선택 | #c5f36b |

현재 CSS에는 prefers-color-scheme 블록과 뒤쪽 재정의가 함께 있다. 앞부분 토큰만 보고 전 화면이 그 색이라고 단정하지 말고 최종 적용값을 확인한다. 이 중복을 정리하려면 별도 범위로 다루고 화면 회귀를 확인한다.

## 레이아웃·컴포넌트
- `Manager`, `Navigation`, `Head`, `SectionTitle`, `Metric`, `Emblem`, `ChampTile`, `Champ`를 먼저 재사용한다.
- 주요 작업 화면은 감독실/선수단/훈련/전략/매치/리그/계약/국제대회/스태프/기록이다.
- 새 폼·다이얼로그·테이블은 기존 `components/ui`와 같은 의미의 컴포넌트를 사용한다. 기존 파일을 전체 포맷팅하거나 UI 패키지를 다시 생성하지 않는다.
- 버튼에는 ‘확정’, ‘훈련 시작’, ‘세트 경기 시작’처럼 결과가 분명한 이름을 쓴다. 저장 중에는 재클릭을 막고 상태를 표시한다.
- 데이터 없음, 로딩, API 오류, 저장 충돌, 완료 상태를 각각 표현한다.

## 글자와 간격 — 향후 수정 기준
기존 세부 요소에는 10~13px 글자가 남아 있다. 이것을 새 UI의 기준으로 복제하지 않는다.
- 본문/중계 16px 이상, 자주 읽는 라벨 14px 이상, 보조 메타 12px 이상을 목표로 한다.
- 숫자는 tabular-nums를 사용하고 자금·점수·숙련도·골드 단위를 붙인다.
- 4/8/12/16/24/32px 간격 체계를 기본으로 삼되 기존 카드 밀도를 유지한다.
- 터치 확정 버튼은 높이 최소 44px. 색상만으로 밴·픽/성공·실패를 구별하지 않는다.

## 밴픽 화면
현재 `LiveDraft`는 250px / 유동 / 250px 3열, 1100px 이하에서는 세로 배치다. 우리/상대 팀, 블루/레드, 현재 밴/픽 차례와 선택 후보가 함께 보여야 한다.
- 후보 카드의 챔피언명·사진·역할·숙련·메타 표기를 유지한다.
- 클릭은 후보 선택, 확정 버튼은 서버 명령 전송으로 구분한다.
- 확정된 픽은 `DraftSummary`에 표시하고 포지션 스왑을 유지한다.
- 향후 개선 시 오프롤 −6을 문장과 수치로 표시한다. flex는 패널티 없음.
- 팀 최고 숙련과 실제 배정 선수 숙련은 서로 다른 수치다. 확정 전 설명에서 구분하는 것을 BACKLOG에 기록했다.

## 중계·그래프
- 실제 확정한 10개 챔피언과 출전 선수를 사용한다.
- ‘접근/상황 → 처치·오브젝트 결과 → 해설’ 구조로 확장한다.
- 퍼스트 블러드/세트 종료 선언은 실제 이벤트 상태와 연결한다.
- 골드 그래프는 현재 연출용 추정값이다. 이를 실제 롤 경제 시뮬레이션 결과로 표현하지 않는다.
- 배속·결과 보기·리캡 이후 다음 행동을 유지한다. 모션 축소 설정을 존중한다.

## 반응형 수락 기준
| 크기 | 확인할 행동 |
|---|---|
| 390×844 | 메뉴 열기, 훈련, 챔피언 검색·확정, 스왑, 중계, 모달 닫기 |
| 768×1024 | 표 가로 스크롤과 버튼 접근, 다이얼로그 높이 |
| 1440×900 | 양 팀과 후보의 정보 균형, 주요 행동 한눈에 식별 |
| 텍스트 확대 200% | 글자 겹침 없음, 확정 버튼 접근 가능 |

브라우저로 확인하지 않았다면 이 기준은 목표이지 테스트 통과 기록이 아니다. 외부 챔피언 이미지에 실패해도 카드의 이름과 폴백은 남겨둔다. 팀 색상은 `lib/rosters.ts`를 기준으로 한다.
