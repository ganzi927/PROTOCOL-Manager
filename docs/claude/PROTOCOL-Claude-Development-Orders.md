# PROTOCOL Manager — 클로드 개발 지시서

작성: 2026-09-14. 이 문서는 기능 아이디어 목록과 실행 지시를 함께 담는다. 아래 우선순위와 완료 조건까지 작업 범위로 사용한다.

## 1. 지금까지 개발한 버전의 마감 상태

기준 코드: `codex/match-broadcast`, 로컬 최신 커밋 `ca6583d`. 원격 업로드는 쓰기 인증 부재로 실패했다. GitHub의 기존 코드만 받아 최신이라고 가정하지 말고, 전달받은 최신 `PROTOCOL-Manager-Broadcast.zip`과 실제 파일을 확인한다.

| 영역 | 구현된 내용 | 남은 사항 |
|---|---|---|
| 밴픽 | 직접 밴픽, 포지션 스왑, 숙련도, 조합 분석, 추천 3개, AI 조합 평가 | 챔피언 개별 특성 검수, 픽 순서·유연한 포지션·시리즈 적응 |
| 전투 | 참여자 기반 갱킹·바텀·오브젝트·한타, 능력→행동→자원, 공성 | 능력별 전환 경로 추가 검수, 연속 운영, 스킬·웨이브 모델 |
| 조합 | 견제·진입·보호·후반 성장 효과 | 기존 태그 기반 설계값이며 실제 패치 승률 데이터가 아님 |
| 미니맵 | 공통 지도 경로, 위치 지속, 도착 후 처치, 적 넥서스 종료 | 사건 기반 재생 연출이 남음. 실제 LoL의 모든 행동을 계산하지 않음 |
| 방송 화면 | 역할 진형 보간, 현재 KDA·행동, 완료 사건 다시 보기, 되감기·종료 제어 | PC·모바일 실제 조작 인수 미완료. 진형 오프셋은 표시 전용 |
| 결과 | 사건 기반 POG·근거, 골드 공개 시점, 조합 수행 요약 | 감독 선택→결과 분석, 운영 지표, 훈련 이력 연결 |
| 구단 운영 | 훈련·숙련도·컨디션·계약·트레이드·스태프·국제대회 | 선택 간 기회비용, 상대 분석, 시즌별 서사 확대 |
| 검증 | 기존 엔진 3 careers/1,086 결정적 세트, 전투·재생 등 회귀; 후속 50경기 방송 검사, 타입·빌드 통과 | 후속 화면 변경마다 모든 장기 실험을 다시 한 것은 아님. 로그별 코드 범위 확인 |

정상 넥서스 종료 99%는 특정 균형 1,000시드 실험값이다. 모든 조합의 보장값이 아니다. 일부 능력 승률 효과는 작고, 기존 테스트 크기 임계값 변경도 기록돼 있다. 이를 “밸런스 완성”으로 표현하지 않는다.

**실행 안내 정정:** `npm run dev`는 개발 서버를 시작하는 명령이다. 현재 `app/api/game/route.ts`는 인증된 사용자 헤더가 없으면 401을 반환한다. 따라서 서버가 뜬다는 것과 새 커리어 생성·저장·복원이 되는 것은 별도다. 기존 START_GAME.md의 안내만으로 독립 로컬 플레이가 검증됐다고 판단하지 않는다.

## 2. 제품의 목표와 개발 판단 기준

플레이어는 챔피언을 직접 조작하는 선수가 아니라 감독이다. 다음 고리가 사용자에게 보여야 한다.

“상대 분석 → 선수·훈련 선택 → 밴픽으로 승리 계획 구성 → 운영 지시 → 선수들의 실행과 변수 → 전투·구조물·넥서스 → 근거 있는 피드백 → 다음 경기 준비”

기능을 추가할 때 아래 네 질문에 답한다.

1. 사용자가 어떤 선택을 하게 되는가?
2. 그 선택 때문에 어떤 경기 행동이나 자원이 달라지는가?
3. 그 차이를 화면과 중계에서 어떻게 알아보는가?
4. 결과를 보고 다음 경기에서 무엇을 바꿀 수 있는가?

단순히 버튼·능력치·랜덤 이벤트만 늘리는 기능은 뒤로 미룬다. 약팀의 역전은 상성, 준비, 실제 수행, 상대 실수의 조합에서 나오게 한다. 특정 조합을 고르면 무조건 이기거나 약팀에게 숨은 보정을 주지 않는다.

## 3. 클로드에게 처음 전달할 통합 명령

아래 블록을 복사해서 전달한다. 이 문서도 프로젝트의 `docs/claude/DEVELOPMENT_ORDERS.md`로 제공한다.

```text
너는 PROTOCOL Manager의 게임 디자이너이자 구현 담당 개발자다.
최신 사용자 수정본을 기준으로 이 지시서의 순서대로 구현·검증·인수인계를 진행하라.
기획만 쓰거나 진행 허락을 반복해서 묻지 말고, 이미 승인된 범위에서 실제 코드를 수정하라.

먼저 CLAUDE.md, HANDOFF.md, CURRENT_STATE.md, BROADCAST_UPDATE.md,
BROADCAST_CONTINUATION.md, DEVELOPMENT_ORDERS.md를 읽어라.
오래된 HANDOFF의 미완료 항목보다 최신 코드와 최신 문서의 증거를 우선하라.
최신 방송 모듈과 tests/broadcast.test.mjs가 없으면 다른 버전을 수정하지 말고
제공된 최신 ZIP을 찾아 기준을 맞춰라. 없을 때만 필요한 소스를 요청하라.

첫 실행은 F01(실행·저장 인수)이다. 실제 게임 생성·저장·복원을 확인한 후
F02(방송 브라우저 인수), F03(사건·자원 정합), F04(세션 기반 경기 엔진) 순으로 진행하라.
독립적인 외부 환경 제한이 있으면 해당 항목을 BLOCKED로 기록하고,
진행 가능한 다음 작업을 계속하되 BLOCKED를 완료로 보고하지 마라.

140개 챔피언 ID와 기존 선수·세이브·숙련도·밴픽 API를 보존하라.
표시 수정은 승패 난수를 바꾸지 않는다. 엔진 변경에는 simulationVersion을 둔다.
모든 골드·처치·어시스트·구조물·중계·리캡은 같은 원본 사건에서 파생시켜라.
기존 이벤트를 화면 편의로 다른 승자·킬러·어시스트로 바꾸지 마라.
미래 결과를 AI 판단·감독 지시·현재 화면에 사용하지 마라.
진행 상태와 명령은 서버 또는 명시적인 로컬 실행 어댑터가 확정한다.
실제 통계가 없는 지표를 관측 승률이나 현재 메타라고 표시하지 마라.

한 작업은 설계 계약→구현→해당 위험의 검증→문서 갱신까지 끝내라.
UI만 변경한 경우 장기 밸런스 전체 실험을 반복하지 않는다.
승패 엔진을 변경하면 같은 시드·같은 입력의 기준선과 비교하고,
승률뿐 아니라 행동 지표와 종료 원인을 기록하라.
실패 테스트를 통과시키려고 임계값을 조용히 낮추지 마라.
시간이 부족하면 기능을 작게 나누고 완료·미완료·재현 명령을 남겨라.
문맥이 충분하면 다음 의존성 충족 작업을 계속 진행하라.

마지막 보고에는 변경된 사용자 경험, 수정 파일, 실제 실행한 검증,
알려진 문제, 다음 첫 행동만 간결하게 써라.
Git 업로드·배포 성공을 확인 없이 주장하지 마라. 외부 연결 실패가 일반 개발을 막지는 않는다.
```

## 4. 작업 순서와 의존성

| 순서 | 작업 묶음 | 필요한 선행 작업 | 출시 판단 |
|---|---|---|---|
| P0 | F01 실행·저장, F02 방송 인수, F03 사건 원장 | 최신 코드 확보 | 실제 한 경기와 저장 왕복이 확인돼야 함 |

## 5. 실행 단위별 클로드 명령

### F01 — 누구나 실제로 시작하고 저장할 수 있는 실행 방식

**명령:** 현재 배포 인증과 로컬 실행 조건을 조사하고, 지원 환경을 명시해 실제 플레이 가능한 시작 경로를 완성하라. 시작 화면, API 인증, DB 바인딩을 분리 진단하라. 단순히 401을 숨기거나 브라우저가 임의 사용자 ID를 보내게 하지 마라. 독립 로컬 모드가 필요하면 루프백 전용 실행 환경과 별도 로컬 저장 어댑터를 명시적으로 설계하고, 호스팅 계정 데이터와 분리하라. 운영 인증을 약화시키지 마라.

**첫 범위:** 새 커리어 생성→훈련→밴픽→경기→저장→새로고침→복원. 실패 시 사용자에게 다음 행동을 안내한다.

**완료 조건:** 지원 환경에서 위 경로가 실제로 성공한다. 로컬/호스팅 데이터가 혼동되지 않는다. 중복 요청과 오래된 revision이 이중 진행을 만들지 않는다. START_GAME.md를 실제 검증 결과에 맞게 고친다.

### F02 — PC·모바일 방송 화면 인수와 조작 완성

**명령:** 실행 가능한 브라우저에서 1440×900, 390×844, 360×800으로 전체 세트를 확인하라. 미니맵·상태창·중계·결과가 동기화되는지 확인하고 실제 결함을 수정하라. 지도는 세 라인·강·정글 구역·진영·포탑을 구분할 수 있게 하고, 지형과 통행 가능 경로를 같은 좌표계로 유지하라. 기존 도형 위에 장식만 덧씌워 벽 통과 문제를 만들지 마라.

**필수 동작:** t=0 정지, 1/2/4배속, 슬라이더, 다음 사건, 완료 사건 클릭, 끝으로 이동, 종료 후 되감기, 재시작, 탭 비활성/복귀, 선수 아이콘 키보드/터치, 이미지 실패 폴백.

**완료 조건:** 실제 재현 시드와 화면 크기별 증거를 남긴다. 결과 미리 노출·아이콘 순간이동·겹친 터치 영역·가로 넘침·죽은 선수 이동을 구분해 점검한다. 도구가 막히면 브라우저 완료로 표시하지 않는다.

### F03 — 경기 사건과 자원 원장의 단일화

**명령:** 원본 `combat.resource`, `lead[]`, 표시 `goldA/goldB`, POG, 킬 피드, 구조물 스냅샷의 생성·소비 경로를 감사하라. 이미 단일화된 부분은 보존하고, 같은 원인에 대해 보상이 두 번 지급되거나 표시 골드가 임의로 늘어나는 곳만 고쳐라.

**목표 계약:** 모든 의미 있는 사건에 `eventId`, 경기 시각, 실제 참가자, 위치/이동 근거, 효과 목록, 연결된 앞선 사건 ID를 둔다. 골드 효과는 수신자·금액·원인·지급 시각을 갖는다. 기존 자원 모델을 실제 전체 골드로 확장할 때는 초기 골드·자연 수급·파밍·처치·오브·구조물의 포함 범위를 먼저 정의한다.

**완료 조건:** 화면 팀 골드=정의된 개인 골드 합, KDA=원본 처치·어시, 구조물 중복 보상 0, 리플레이 임의 시각에서 미래 효과 0. 어시스트 총액 등은 이 게임의 배분 규칙을 명시하고 검증한다. 골드 그래프가 맞는지는 같은 필드를 재읽는 검사만으로 끝내지 않는다.

### F04 — 경기 중 결정이 가능한 단계 진행 엔진

**명령:** 한 번의 `play`로 `simulateSet`을 끝까지 계산하는 구조를 유지한 채 버튼만 추가하지 마라. 경기 세션 초기화→다음 의사결정 지점까지 진행→사용자/AI 지시 적용→종료의 순수 단계 함수를 도입하라. 기존 일괄 `simulateSet`은 새 단계 함수를 끝까지 반복하는 호환 경로로 사용할 수 있다.

**저장 계약:** `MatchSession`에 경기 시각, 상태, 이미 발생한 사건, 대기 행동, 선수 상태, 명령 영수증, 난수 스트림 상태 또는 결정적 카운터, 엔진 버전을 저장한다. 함수/클로저 자체를 저장하지 않는다. 결과가 아니라 현재까지의 상태만 클라이언트에 전달한다.

**첫 범위:** 오브젝트 준비 구간에서 한 번 멈추고 “싸움 준비/반대편 이득/정비” 중 지시를 받아 이후 사건에만 적용한다. 전체 실시간 조작 UI는 뒤로 미룬다.

**완료 조건:** 중간 저장·새로고침·재개와 중단 없는 실행이 동일하다. 같은 명령 재전송은 한 번만 적용된다. 과거 사건 불변. 화면 배속과 FPS가 결과를 바꾸지 않는다. 구세이브·구리플레이를 재계산해 결과를 바꾸지 않는다.

### F05 — 챔피언마다 다른 경기 성격

**명령:** 140개 챔피언 ID는 유지하고 기존 2개 태그만으로 전투 성격을 판단하는 한계를 보완하라. 먼저 실제 플레이 방식이 크게 다른 대표 20종을 선정해 개별 프로필을 검수하고 점진적으로 전체로 확대하라. 구체적 챔피언 특성은 구현 당시 공식 정보로 확인하고 출처·검수일·게임 내 해석을 남겨라.

**프로필 후보:** 견제 사거리, 강제 진입, 후퇴/회피, 보호, 전열 유지, 순간/지속 화력, 파밍 안전성, 성장 곡선, 라인 정리, 공성, 사이드 운영, 오브젝트 마무리. 데이터가 없는 값은 추정 설계값으로 표시한다.

**첫 범위:** 단일 균등 합산보다 실제 행동에 쓰이는 4~6개 핵심 축으로 시작한다. 선수 숙련도는 이 특성을 실행하는 정확도·판단에 반영한다. 모든 축을 승률 보너스로 더하지 마라.

**완료 조건:** 사이드 운영 챔피언이 잘못된 포킹 특성 때문에 포킹 조합의 중심으로 평가되는 사례를 고정 검사한다. 비슷한 역할이라도 다른 행동이 관측된다. UI·AI·엔진이 동일 프로필을 사용한다.

### F06 — 상성과 시간대가 있는 조합 시스템

**명령:** 포킹, 강제 진입, 보호형 후반, 픽/매복, 사이드 압박을 우선 지원하라. 팀에 이름 하나만 강제로 붙이지 말고 혼합 강점·약점과 부족한 역할을 보여라. “강제 진입은 항상 포킹을 이긴다” 같은 전역 가위바위보 보너스 대신, 시야·거리·진입 수단·보호·성장 시점이 충족될 때 유리해지도록 하라.

**행동 연결:** 포킹=교전 전 체력/공간 압박, 진입=거리 좁히기와 전투 강제, 보호=핵심 딜러 생존·지속 공격, 후반=시간/경제 성장, 사이드=웨이브/구조물 압력과 본대 인원 손해. 체력 모델이 없으면 실제 체력처럼 표시하지 말고 단계 도입 전 추상 준비 압력으로 명명한다.

**완료 조건:** 같은 선수·상대·시드에서 조합을 바꾸면 관련 행동 지표와 결과가 달라진다. 유리 조건이 사라지면 이점도 줄어든다. 약팀이 준비로 승산을 높일 수 있지만 보장승은 아니다.

### F07 — 사람이 읽을 수 있는 AI 밴픽

**명령:** 현재 합법 후보·숙련도·포지션·조합 평가를 확장해 위협 제거 밴, 핵심 조합 선점, 상대 응수, flex의 실제 배치 가능성, 미완성 조합 보완을 판단하라. 상대의 확정 픽과 관측 기록만 사용한다.

**첫 범위:** 후보 3~5개에 상대 응수 1단계를 평가하는 제한 탐색을 적용하고 시간 예산을 둔다. 역할 배정이 불가능한 추천은 제외한다. 사용자는 추천을 무시하고 직접 선택할 수 있다.

**화면:** 추천 이유는 “좋은 픽”이 아니라 “진입 부족 보완/상대 핵심 딜러 압박/우리 선수 숙련/남은 포지션”으로 설명한다. 실측 승률, 모델 조합 전망, 우리 선수 반영 전망을 데이터 유무에 따라 구분한다. 근거가 없으면 퍼센트 대신 정성적 전망을 표시한다.

**완료 조건:** 확정되지 않은 상대 픽을 미리 아는 AI가 없다. 추천·자동 픽이 같은 합법성 검사를 통과한다. 포지션 중복과 시리즈별 밴 적용 범위를 검증한다.

### F08 — 열 명 모두 지속적인 목적을 가진 이동

**명령:** F04 이후 엔진에 현재 위치·목적·출발·예상 도착·변경 이유를 가진 행동 계획을 두어라. 라인 관리, 정글 동선, 시야 지원, 합류, 귀환, 부활 후 복귀가 사건 사이에도 이어지게 하라. 모든 선수를 사건마다 집으로 돌려보내거나 무작위 왕복시켜 움직이는 척하지 마라.

**핵심 경계:** AI는 현재 관측과 팀 계획으로 목적지를 정한다. 완성된 미래 사건의 참가자 명단을 읽어 미리 이동시키는 방식은 실시간 판정에 쓰지 않는다. 과거 경기의 재생 구성과 현재 경기 AI를 분리한다.

**완료 조건:** 이동 거리/시간 일치, 벽 통과 0, 순간이동은 정의된 귀환/부활 등 명시적 행동에만 허용, 목적 변경에도 위치 연속, 늦은 선수는 늦게 합류. 다른 라인의 행동이 지속된다. 재생 경로는 원본 이동 사건을 따라가며 별도 승패를 만들지 않는다.

### F09 — 라인 웨이브와 귀환 타이밍

**명령:** 미니언 개체를 수백 개 생성하기 전에 라인별 웨이브 위치·크기·방향·다음 생성 시각·포탑 접촉을 집계 상태로 구현하라. 밀기, 받아먹기, 귀환, 합류가 자원과 시간의 교환이 되게 하라.

**첫 범위:** 웨이브를 밀고 오브에 합류한 경우와 라인을 버리고 합류한 경우를 구분한다. 귀환에는 수행 시간·중단 조건·복귀 이동을 둔다. 포탑을 때릴 조건에 아군 웨이브를 포함한다.

**완료 조건:** 합류해도 모든 라인 자원을 자동 수령하지 않는다. 사이드를 미는 선수와 본대가 동시에 같은 곳에 존재하지 않는다. 중계가 실제 손해·이득을 설명한다.

### F10 — 목표를 둘러싼 운영: 오브젝트·시야·교환

**명령:** 지원할 경기 규칙 버전을 정하고 오브젝트 생성·생존·재생성·효과를 데이터로 관리하라. 시야는 먼저 구역별 정보 상태로 시작한다. 팀별 관측 범위와 방송 관전자 시점은 구분한다.

**첫 범위:** 생성 전 준비→시야 확보/차단→합류 가능성→싸움/양보/반대편 교환. 포기에도 실제 자원·구조물 이득이 있을 수 있게 한다. 바론 같은 효과를 넣을 때는 적용 시간·만료·사망 후 규칙을 정의한다.

**완료 조건:** 죽은 목표를 또 확보할 수 없다. 목표를 포기했는데 보상을 받지 않는다. 스틸을 말하려면 목표 잔여 체력과 확보 행동 시점이 실제로 있어야 한다. 숨은 상대 위치를 AI가 참조하지 않는다.

### F11 — 납득되는 공성·수비·넥서스 마무리

**명령:** 공성에 실제 생존 공격자, 도착 시간, 웨이브, 수비 합류, 성장/아이템, 목표 구조물 상태를 연결하라. 한타 승리 후 재정비가 더 좋은 상황도 허용하라. 한타 승리 횟수를 넥서스 파괴로 치환하지 마라.

**첫 범위:** 외곽→내곽→억제기→기지 방어 구조물→넥서스 진행, 수비 복귀 시 철수. 사이드 운영은 F09가 갖춰진 뒤 추가한다.

**완료 조건:** 정상 종료는 실제 적 넥서스 파괴 사건으로만 발생한다. CAP는 진단 가능한 비정상/제한 종료로 남기고 숨기지 않는다. CAP 원인을 조사하지 않고 상한만 계속 늘리지 않는다. 모든 조합·우열·시간대의 종료율을 분리 확인한다.

### F12 — 감독의 경기 중 지시

**명령:** F04의 의사결정 지점에서 운영 우선순위를 바꿀 수 있게 하라. 첫 버전은 ①오브 준비 ②반대편 교환 ③딜러 보호 ④위험 감수 진입 정도로 제한한다. 각 지시는 장점, 포기하는 것, 반응 지연, 변경 제한을 가진다.

**효과:** 지시→행동 계획 변화→선수 수행→사건. “공격적 지시: 승률 +10%”처럼 끝내지 않는다. 명령이 내려져도 이미 진행 중인 전투나 먼 위치가 즉시 바뀌지 않는다. 선수 판단·호흡 때문에 실행이 불완전할 수 있고 그 이유를 기록한다.

**완료 조건:** 동일 시드 분기 실험에서 지시 전 과거는 동일하고 이후 경로만 달라진다. 무지시 기본 운영도 완주한다. 재전송·연타로 효과가 중첩되지 않는다. 실제 대회 통신 규정의 재현이라고 주장하지 않고 이 게임의 감독 모드 규칙으로 안내한다.

### F13 — 경기의 앞뒤를 기억하는 해설

**명령:** 문장 수를 늘리기 전에 각 중요 사건을 준비→실행→결과→의미로 설명하라. 해설 내용은 선수·챔피언·장소·참여·생존·자원·지시·앞선 사건의 실제 근거에 묶어라.

**첫 범위:** 캐스터는 관측 가능한 행동, 해설자는 가능한 이유와 트레이드오프를 설명한다. 앞선 갱킹이 만든 자원, 서포터 보호 후 딜러 공성, 훈련한 조합, 감독의 오브 포기 후 반대편 철거를 연결한다. 훈련 이력이 없으면 “이번 주 연습한 조합”을 말하지 않는다.

**완료 조건:** 퍼스트블러드 1회, 실제 참여자만 언급, 양보/무교전/상호 후퇴 구분, 근거 없는 스틸·스킬·역전 표현 없음. 요약/상세/결정적 중계가 동일 사실을 전달한다. 선택적 생성형 문장·음성은 사실 검증과 폴백이 갖춰진 뒤 도입하며 엔진 결과를 정하지 않는다.

### F14 — 다음 경기에 도움이 되는 리캡

**명령:** 리캡을 경기 전 승리 계획→중요 분기점 3개→핵심 기여→잃은 자원→다음 세트 제안으로 재구성하라. 각 카드에 근거 사건으로 돌아가는 연결을 붙여라.

**화면 예:** “딜러 보호 성공 2회 → 생존한 딜러의 후속 공성 참여”처럼 관측 경로를 보여라. 결과가 달라졌을 것이라는 반사실 주장은 별도 비교 시뮬레이션을 하지 않았다면 단정하지 마라.

**완료 조건:** 리캡 수치와 원본 사건을 독립 재집계해 일치시킨다. 실제 피해량을 계산하지 않았으면 가상 기여 점수를 피해량으로 표시하지 않는다. 패배 팀도 좋은 수행과 개선 가능한 실수를 구분한다.

### F15 — 밸런스와 예측 품질의 검증 도구

**명령:** 균형, 역할별 단일 능력 강화, 팀 전체 강화, 오프롤, 숙련, 조합 상성, 진영 교환, AI 난이도를 비교하는 재현 가능한 실험을 만들어라. 종료율·길이·합류·처치·보호·오브·공성·역전·POG를 함께 기록하라.

**방법:** 같은 시드 쌍의 승패 불일치 원자료를 보존하고 paired delta의 신뢰구간을 명시한다. McNemar의 차이 검정과 승률 차이 신뢰구간은 구분한다. 기준선 코드/입력/규칙 버전을 고정하고 튜닝 시드와 평가 시드를 나눈다.

**완료 조건:** 작은 양수나 원하는 승률 하나로 개선을 확정하지 않는다. 역할 POG 비중을 억지로 20%씩 맞추지 않는다. 승률 예측을 표시할 경우 보류 데이터에서 보정도와 오차를 점검한다. 미검증이면 “모델 추정” 또는 정성 평가로 제한한다.

### F16 — 다음 상대를 준비하는 분석실

**명령:** 상대의 이미 끝난 경기에서 선호 픽, 주력 라인, 운영 속도, 오브 선택, 보호 대상, 취약한 구간을 요약하라. 다음 경기의 확정 픽/난수/실제 명령을 미리 보여주지 않는다.

**완료 조건:** 표본 수·관측 경기 범위를 표시한다. 분석가 수준은 정보 정리·추정 오차·준비 효율에 작용하며 미래를 알아내는 능력이 아니다. 스카우팅→훈련 또는 밴픽 결정으로 연결된다.

### F17 — 훈련의 기회비용과 경기 콜백

**명령:** 기존 훈련·숙련·피로를 보존하며 개인 챔피언 연습, 팀 조합 합, 오브 운영, 휴식을 제한된 주간 자원 안에서 선택하게 하라. 모든 항목을 동시에 최대치로 올릴 수 없게 한다.

**완료 조건:** 훈련 이력에 선수/조합/날짜/강도/효과가 남는다. 특정 연습 효과는 실제 관련 행동에서만 사용한다. 로스터·챔피언 교체 시 이전 훈련 효과가 새 대상에게 잘못 적용되지 않는다.

### F18 — 선수의 스타일·성장·컨디션

**명령:** 기존 능력·잠재력·나이·컨디션에 성향과 성장 과제를 소수 추가하라. 예: 공격적 진입, 안정적 파밍, 시야 지원, 주도적 콜. 성향은 강점과 위험을 함께 가진다.

**완료 조건:** 선수 선택이 평균 능력치 순서로만 정해지지 않는다. 숨은 성향을 쓰면 관측을 통해 점차 드러나게 한다. 단기 컨디션과 장기 능력, 팀 호흡과 개인 숙련을 중복 가산하지 않는다. 실존 인물의 사생활·성격 사실로 표현하지 않고 게임 내 설정임을 구분한다.

### F19 — 스카우팅·유망주·영입 판단

**명령:** 현재 로스터와 시즌 기록을 보존하고, 필요한 역할/챔피언 풀/예산으로 선수를 찾는 비교 도구를 추가하라. 유망주의 잠재력은 확정 숫자 공개보다 관측 범위·불확실성·육성 비용을 갖게 하라.

**완료 조건:** 싼 유망주가 무조건 최선이 아니며 즉시 전력과 육성의 차이가 있다. 영입 비용·로스터 제한·선발 공백을 현재 계약 규칙과 함께 검증한다. 기존 트레이드·재계약 중복 지급 방지는 유지한다.

### F20 — 재정·계약·스태프의 실제 선택

**명령:** 기존 재정 시스템에서 사용자가 비교하기 어려운 부분부터 개선하라. 다음 시즌 확정 급여, 계약금, 예상 현금 흐름, 육성 투자, 분석가/코치/심리 스태프의 기회비용을 한 화면에서 보여라.

**완료 조건:** 현금과 연봉 총액을 구분하고 예약된 계약을 포함한다. 파산 직전 반복 지원으로 모든 선택이 무의미해지지 않게 구제 규칙을 명시한다. 스태프의 효과는 해당 시스템에서만 발생한다.

### F21 — 세트 사이 적응과 시리즈 규칙

**명령:** BO3/BO5에서 이전 세트의 실제 실패 원인을 바탕으로 AI가 밴·선발·우선 라인을 조정하게 하라. 대회별 밴픽 규칙은 설정으로 분리하고, 지원하지 않는 규칙은 활성화하지 마라.

**첫 범위:** 같은 상대에게 효과적인 조합을 반복할 때 상대가 관측을 통해 대응한다. 무조건 사용자 조합을 카운터 치는 숨은 보정은 금지한다.

**완료 조건:** 세트 종료만으로 선수 컨디션·숙련·규칙상 사용 불가 픽이 잘못 초기화되지 않는다. 시리즈 준비 화면에서 변경 이유를 설명한다.

### F22 — 시즌 서사와 규칙 버전별 메타

**명령:** 연승, 주전 경쟁, 신인 성장, 라이벌, 플레이오프 경쟁을 실제 시즌 기록에서 생성하라. 무작위 뉴스만 반복하지 마라. 게임 내 패치는 일부 특성/아이템/오브 규칙 변화로 관리하고 미리 안내한다.

**완료 조건:** 변화 이유와 적용 시점이 기록된다. 진행 중 경기의 규칙은 바뀌지 않는다. 패치 전 리플레이는 당시 버전으로 보존한다. 실데이터를 연결하지 않았으면 “게임 내 메타”라고 부른다.

### F23 — 모바일과 경기 길이 조절

**명령:** 세로 화면에서는 지도·핵심 중계·필수 조작을 우선하고 자세한 분석은 접을 수 있게 하라. 전체 중계, 하이라이트, 빠른 결과는 동일한 경기 결과를 다른 밀도로 보여준다.

**완료 조건:** 터치 목표·키보드 포커스·색상 외 진영 구분·모션 감소·텍스트 크기를 점검한다. 저사양에서 움직임 프레임을 줄여도 엔진 시계와 결과는 동일하다. 앱 설치형 패키지는 웹 조작이 안정된 뒤 판단한다.

### F24 — 저장 안정성과 세이브 이동

**명령:** 기존 슬롯·revision·명령 영수증·복원 지점을 보존하라. 스키마 버전과 경기 엔진 버전을 구분하고, 세이브 내보내기/가져오기는 크기 제한·형식 검사·버전 검사·원본 보존을 갖추어라.

**완료 조건:** 네트워크 끊김·중복 클릭·다른 기기 동시 진행·구버전 저장을 재현한다. 불러오기 실패가 기존 저장을 덮어쓰지 않는다. 오프라인과 클라우드 충돌은 사용자가 이해할 수 있는 선택지로 해결한다.

### F25 — 첫 경기 튜토리얼과 연습 모드

**명령:** 첫 경기에서 조합 목표 하나, 밴픽 이유 하나, 감독 지시 하나, 리캡 근거 하나를 직접 경험하게 하라. 많은 설명 창을 연속으로 띄우지 마라. 샌드박스에서는 두 팀과 조합을 고정하고 같은 조건을 다시 비교할 수 있게 한다.

**완료 조건:** 튜토리얼은 건너뛸 수 있고 커리어 보상이 중복되지 않는다. 연습 결과가 본 시즌 승패·성장에 섞이지 않는다. 초보자가 승리뿐 아니라 “왜 그 선택을 했는지” 이해할 수 있다.

### F26 — 리플레이·공유·관전 기록

**명령:** 세이브 전체 대신 경기 ID·엔진 버전·규칙 버전·허용된 경기 사건으로 독립 리플레이를 만들라. 주요 장면 북마크와 사건 링크를 우선 구현한다. 영상 내보내기는 재생 안정화 뒤 선택 기능으로 둔다.

**완료 조건:** 예전 리플레이를 새 패치로 재계산하지 않는다. 공개 공유에는 계정 식별자·비공개 저장 정보가 들어가지 않는다. 전투 근거·KDA·넥서스 결과가 원본과 일치한다.

### F27 — 실제 조합 통계와 메타 데이터 연결

**명령:** 외부 서비스를 화면에서 흉내 내기 전에 사용할 수 있는 데이터·접근 방식·출처·조건을 확인하라. 현재 코드의 태그 기반 점수를 실측 승률로 이름만 바꾸지 마라. 데이터가 없으면 설계값 모드로 정상 동작하게 한다.

**첫 범위:** 패치·포지션·표본 수·대회/일반 경기 맥락·집계 시각을 갖춘 데이터 어댑터와 오프라인 fixture. 희소한 5인 조합은 샘플 부족으로 표시하고, 개별 성능·2인 시너지·대응 조합·선수 실력을 무리하게 같은 원인으로 합치지 않는다.

**완료 조건:** 관측 승률/모델 조합 전망/우리 팀 전망이 분리된다. 데이터 실패·오래된 패치·작은 표본에 폴백이 있다. 외부 값을 적용한 새 규칙 버전과 기존 리플레이가 분리된다. 특정 사이트의 화면 숫자가 곧 이 게임의 승률이라는 가정은 금지한다.

## 6. 구현 중 계속 지킬 기술 계약

- 원본 사건은 append-only를 기본으로 한다. 표기 수정은 파생 뷰에 적용하고 경기 사실을 바꾸지 않는다.
- 커리어/경기/규칙/데이터 버전을 분리하고 저장 마이그레이션은 반복 실행해도 안전해야 한다.
- 슬롯 숫자만으로 장기 기록을 연결하지 말고 선수 ID·챔피언 ID·팀·경기 ID를 보존한다.
- 실시간 엔진과 완료 리플레이의 권한·정보 범위를 분리한다. 새 기능은 보지 못한 미래 결과를 요구하지 않아야 한다.
- `outcome/combat/flavor/narration` 난수의 역할을 문서화한다. 표시 수정으로 기존 승패 난수 호출 수가 바뀌면 결함으로 본다.
- 새 모듈은 game.ts 순환 의존을 피한다. 필요한 타입/프로필/순수 함수를 분리하되 검증 없이 전체 파일을 재작성하지 않는다.
- CAP, 합류 실패, 훈련 효과 미발동, 지시 지연은 숨기지 말고 진단 가능한 이유를 남긴다.
- 추상 수치와 실제 관측량을 구분한다. 가상 딜 기여는 실제 피해량이 아니고, 진형 오프셋은 실제 전투 좌표가 아니다.

## 7. 각 작업의 보고 양식

```text
작업 ID / 목표:
사용자에게 달라진 경험:
변경 파일 / 데이터 계약:
실제로 실행한 검증과 결과:
기준선 대비 변화(엔진 변경 시):
알려진 문제·미검증·외부 차단:
다음 작업 ID / 바로 실행할 첫 행동:
```

컨텍스트가 줄면 HANDOFF에 위 내용과 재현 명령을 먼저 남긴다. “다 됐음”으로 끝내거나, 실제 미완료를 기록하지 않은 채 다음 기능을 시작하지 않는다.

## 8. 세션을 이어갈 때 보낼 짧은 명령

```text
DEVELOPMENT_ORDERS.md와 최신 HANDOFF를 읽고 현재 코드에서 완료 여부를 확인해.
완료 항목을 재구현하지 말고, 의존성이 충족된 첫 미완료 작업을 구현·검증해.
외부 인증/도구로 막힌 항목은 정확히 남기고 진행 가능한 작업은 계속해.
변경 근거와 재현 명령을 갱신하고, 실행하지 않은 테스트를 통과했다고 말하지 마.
```

## 9. 지금 바로 시작할 추천 범위

F01 실행·저장 왕복과 F02 방송 인수를 먼저 닫는다. 그다음 F03 사건 원장을 점검하고, F04에서 오브젝트 준비 시점 한 번에 감독 지시가 실제로 개입하는 첫 완결 기능을 만든다. 동시에 많은 운영 메뉴를 늘리기보다, “내 판단이 선수의 행동으로 이어지고 그 결과를 이해할 수 있다”는 경험을 먼저 완성한다.
