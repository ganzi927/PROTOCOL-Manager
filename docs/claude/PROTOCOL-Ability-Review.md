# PROTOCOL Manager — 선수 능력치 영향 분석과 개선안

검토일: 2026-09-09. 대상: 사용자 수정본 PROTOCOL-Manager-Source(2).zip과 이를 보존한 Claude-Ready 패키지의 lib/game.ts. 이번 검토에서는 게임 소스를 수정하거나 배포하지 않았다.

## 결론
능력치는 승패에 영향을 준다. 다만 개인의 특정 강점, 특히 라인전·시야가 세트 승리로 이어지는 효과가 매우 약하다. 팀 전체 능력을 올리면 승률은 크게 오르므로 단순히 ‘모든 능력치 계수를 올리면 해결된다’고 보기는 어렵다.
핵심은 **선수의 행동 → 자원/위치 우위 → 다음 행동의 성과 → 승리 조건**의 연결이 부족하다는 점이다.

## 1. 통제 실험
양 팀 모든 선수의 6개 스탯을70으로 맞추고 폼50·번아웃0·호흡50·균형 전술·미드 우선으로 고정했다. 숙련도와 메타 보너스는 없앴다. 포지션별 서로 다른 챔피언을 사용하되 타입과 조합 태그를 동일하게 맞췄다. 각 실험에서 한 가지 조건만 바꿨고 0~5999의 같은 시드로 독립 세트6,000회를 실행했다. 총60,000세트.

| 변경 조건 | 우리 팀 세트 승률 | 기준 대비 |
|---|---:|---:|
| 양 팀 전원 70 | 50.62% | +0.00%p |
| 탑 1명만 전체 능력 90 | 58.63% | +8.01%p |
| 정글 1명만 전체 능력 90 | 58.95% | +8.33%p |
| 미드 1명만 전체 능력 90 | 61.07% | +10.45%p |
| 원딜 1명만 전체 능력 90 | 65.02% | +14.40%p |
| 서포터 1명만 전체 능력 90 | 60.85% | +10.23%p |
| 우리 팀 5명 전체 능력 80 | 74.55% | +23.93%p |
| 탑의 라인전만 90 | 51.12% | +0.50%p |
| 원딜의 한타만 90 | 57.88% | +7.26%p |
| 서포터의 시야만 90 | 50.90% | +0.28%p |

탑 라인전만70→90인 경우, 탑 이벤트 승률은51.00%→66.97%로 증가했으나 세트 승률은50.62%→51.12%에 그쳤다. 서포터 시야만70→90도 세트 승률50.90%다.
이는 고정된 인위적 대칭 조건의 민감도 검사다. 실전 커리어의 평균 승률이나 모든 조합의 성능을 추정한 것이 아니다. 6,000회 승률50% 근처의 단일 비율 표본오차는 독립 시드 가정에서 약 ±1.3%p(95% 근사)다. 표의 작은 수치 차이에 의미를 과도하게 부여하지 않는다. 비교에는 같은 시드를 사용했지만 짝지은 차이의 별도 신뢰구간은 계산하지 않았다. 인과 구조에 대한 판단은 아래 실제 수식과 함께 해석한다.

## 2. 현재 구조의 문제

### 라인에서 잘해도 성장으로 쌓이지 않는다
powers()는 세트 시작에 양 팀 파워를 한 번 계산한다. 선수의 기본 스탯/숙련/메타/당일 컨디션은 들어가지만, 경기 도중의 골드나 킬로 다시 계산하지 않는다.
TOP 라인전 +20은 TOP 라인 파워에만 0.9×0.5×20=+9를 준다. 한타 파워에는 직접 영향이 없다. 그 이벤트에서 이겨도 누적 우위에 +1만 기록한다. 라인전 압승과 근소한 승리가 같은 크기의 이득이다.

### 골드 그래프는 경기 결과에 쓰이지 않는다
goldA/goldB는 flavor 난수로 증가하는 표시용 값이다. pa/pb나 이후 승률에 입력되지 않는다. 따라서 초반 CS·처치로 부유해진 선수가 아이템을 앞서 구입하여 후반 전투력이 높아지는 흐름은 구현되어 있지 않다.

### 누적 우위의 영향이 작다
pA = clamp(1 / (1 + 10^(-(pa−pb + 0.35×advantage + access)/30)), .05, .95).
advantage는 −12~12이므로 누적 우위 보정은 최대±4.2 파워다. 오브젝트 접근 보정도 근처 라인 승패 평균×0.5 수준이다. 초반 판정은 이겼는지 여부만 전달한다.

### 마지막 교전의 비중이 크다
후반 교전에서 한 팀이3번 이기면 종료하지만, 9번째 이벤트에서는 압박 횟수와 관계없이 그 이벤트 승리 팀을 세트 승자로 정한다. 첫 후반3교전이 같은 팀의 승리가 아니면 마지막 결전까지 가며, 이전 우위는 작은 확률 보정으로만 남는다. 정확히 대칭·독립50%라는 단순 가정에서는 첫3교전이 같은 승자일 확률25%, 마지막 결전까지 가는 확률75%다. 이것은 실제 커리어의 실측 비율이 아니라 종료 구조를 설명하는 예시다.

### 잘한 선수를 보여주는 데이터도 약하다
한타는 가중 평균이다. 개별 선수의 킬/생존/스킬 기여를 먼저 판정하지 않는다. POG는 승리 이벤트의 역할별 고정 기여점수를 합산한다. 중계의 킬과 활약 문구가 개별 전투 계산에 연결되어 있지 않아 ‘고능력 선수의 활약’이 화면에서도 잘 보이지 않는다.

## 3. 권장 개선: 평균 파워 판정을 사건·자원 기반 판정으로 확장

### A. 선수별 상태를 경기 중 유지
선수마다 gold, xp, hp 또는 alive, respawnAt, kills/deaths/assists, damageContribution을 기록한다. 정밀 LoL 물리 시뮬레이션까지 만들 필요는 없지만, 중계에서 말하는 사실은 상태에 남아야 한다.
라인전 우세를 CS/경험치/귀환 타이밍 이익으로 기록하고, 유의미한 파워 차이는 이득의 크기도 바꾼다. 개별 골드를 팀 평균으로 바로 뭉개지 않는다.

### B. 능력마다 담당할 행동을 부여
| 능력 | 사건에 미치는 역할 | 지속되는 결과 |
|---|---|---|
| LNE | CS 확보·라인 압박·교환 우위 | 개인 골드/경험치·라인 위치 |
| MEC | 딜 성공률·교환 효율·위험 회피 | 피해·킬·생존 |
| VIS | 갱/매복 발견·진입 정보·아군 보호 | 피습 감소·오브젝트 유리한 시작 |
| OBJ | 중립 목표 확보·타이밍·마무리 | 목표 보상·팀 자원·구조물 압박 |
| TF | 위치 선정·연계·진입/보호 | 유효 공격 시간·집단 교전 효율 |
| CAR | 확보한 자원의 피해 전환·마무리 | 후반 딜 기여·승리 전환 |

역할별 가중치는 유지하되 모든 스탯을 똑같이 세트 승률에 더하지 않는다. 서포터 VIS는 상대 공격을 덜 맞게 하고 원딜의 공격 시간을 보장하는 식으로 연결한다.

### C. 자원이 후속 전투력으로 전환되게 한다
각 사건에서 개인의 기본능력과 챔피언 보정에 아이템/성장 단계를 반영해 유효 전투력을 다시 계산한다. 예를 들어 개인 골드에 따라 아이템 단계가 오르는 추상 모델을 쓸 수 있다. 증가율·구매 비용·상한은 초기 튜닝값으로 정하고 검증해야 하며 실제 롤 수치라고 주장하지 않는다.
우위 수치와 골드/아이템 보정을 동시에 강하게 넣으면 같은 성과를 두 번 보상한다. 자원 기반 보정을 도입할 때 기존 advantage 역할을 축소하거나 재정의한다.

### D. 교전은 실제 참여자 중심으로 계산
탑2대1 갱이면 TOP/JGL 대 상대TOP, 바텀 교전이면 ADC/SUP와 실제 합류자를 중심으로 판정한다. 5대5도 진입·보호·유효딜·처치/후퇴를 나눠 주역을 기록한다. 이미 사망한 선수는 공격하지 않고, 죽은 피해자를 같은 사건에서 다시 처치하지 않는다.
중계는 판정이 끝난 event에서 생성한다. 결과 문구를 먼저 만들고 임의 KDA를 뒤에 맞추지 않는다.

### E. 경기 종료를 구조물과 공격 기회로 결정
교전에서 이긴 팀이 남은 인원·라인 위치·공격 가능 시간을 바탕으로 포탑/억제기/넥서스를 공략한다. 넥서스가 파괴되면 종료한다. 무한 경기 방지를 위한 제한은 필요하지만 ‘마지막 동전 던지기 승자가 우승’ 대신 최대 시간의 결전 규칙을 명시하고 누적 상태를 반영한다.

### F. 활약이 보이게 리캡을 바꾼다
선수별 라인 골드차, 딜·보호·시야 기여, 오브젝트 기여, 결정적 사건을 보여준다. POG는 이 기록을 근거로 계산한다. 능력치+챔피언 숙련+메타+성장+전술의 기여를 구분하고, 각각이 승률을 몇% 바꿨는지 실제 반사실 계산 없이 단정하지 않는다.

## 4. 하지 말아야 할 단순 처방
- 모든 개인 스탯 계수를 두 배로 올리는 것: 이미 전원+10에서 세트 승률74.55%라 팀간 일방적인 결과를 만들 위험이 있다.
- 확률식 분모30을 줄이기만 하는 것: 한타 스탯 영향까지 더 강해지지만 LNE/VIS의 후반 연결 부재는 남는다.
- 중계에서 스타 선수 이름이 더 자주 나오게만 하는 것: 결과를 만드는 원인은 그대로다.
- 개인마다 팀 승률 보너스를 직접 더하는 것: 선수 역할·자원·사건과 무관한 숨은 보너스가 된다.

## 5. 단계별 구현과 검증
1. **측정/스키마**: 현재 테스트와 비교표 보존. 경기 내 선수상태와 구조화 이벤트 타입을 추가하고 구세이브 변환 정책 정의. 사용자 v3 mastery 배열·140챔피언·스왑 유지.
2. **초반 연결**: 라인/시야 우위를 개인 자원과 피습 방지로 연결. 그 자원이 다음 교전 전력에 반영되는지 확인.
3. **전투·승리 조건**: 참여자별 기여, 처치/생존, 구조물 공격과 종료 판정 추가.
4. **표시**: 같은 이벤트 데이터로 중계·골드 그래프·POG·리캡 생성.
5. **밸런스**: 같은 시드로 변경 전후 실험. 팀 전체+10, 각 역할+20, 각 주요 스탯+20, 숙련/메타, 휴식/피로, 역전 상황을 분리해서 확인.

권장 초기 목표는 ‘모든 스탯+20이 같은 승률 상승’이 아니다. TOP LNE+20이면 초반 우위·개인 자원·후속 기여가 차례로 늘고, SUP VIS+20이면 피습·불리한 진입이 줄어드는 것을 우선 확인한다. 세트 승률 변화 목표(예: 특정 주역할 스탯+20에 +3~6%p)는 제품상의 튜닝 가설로 잡을 수 있지만, 지금 실험으로 검증된 최적값은 아니다.

회귀 조건: 같은 시드/상태에 같은 결과, 입력 세이브 불변, 중복 명령에 이중 보상 없음, 실제 출전 픽만 중계 등장, 첫 킬·POG·종료 결과 일치, 모든 경기 유한 종료, 국내/국제대회·다음 시즌 진행 보존. 골드가 적다는 이유만으로 좋은 선수의 스탯을 영구 낮추지 않는다.

## 6. Claude 전달용 작업 지시
```text
선수 능력치 영향 분석 보고서를 읽고 현재 사용자140챔피언/Lv4 mastery/DraftState 버전을 기준으로 개선해줘.
먼저 분석 실험을 재현하고 라인전·시야 우위가 후속 개인 자원과 교전 파워로 이어지도록 작은 단위로 구현해줘.
중계·골드·POG는 동일한 구조화 사건을 근거로 만들고 기존 승부 난수와 저장 호환성 변경을 명시해줘.
전체 수치를 일괄 증폭하거나 과거60챔피언 버전으로 되돌리지 마.
각 단계에서 기존 테스트와 민감도 비교를 수행하고 HANDOFF/DECISIONS에 결과를 기록해줘.
```

## 부록: 재현 스크립트
아래를 프로젝트 tests/balance-review.mjs에 저장하고 프로젝트 루트에서 `node --experimental-strip-types tests/balance-review.mjs`로 실행한다. 저장파일·DB 없이 동작하며 프로젝트 코드를 수정하지 않는다. 통제된 완성 픽을 simulateSet에 직접 주입하므로 밴픽 UI나 저장 API 검사와는 별개다.

```javascript
import {newGame,upgradeGame,starters,team,ROLES,CHAMPIONS,simulateSet} from '../lib/game.ts';
import {writeFileSync} from 'node:fs';
const base=upgradeGame(newGame('nva',1));
for(const p of base.players){p.stats=Array(6).fill(70);p.form=50;p.burn=0;p.mastery=[];}
base.meta=[];
for(const t of base.teams){t.tactic='balanced';t.focus='MID';t.familiarity[ROLES.map(r=>t.lineup[r]).join('|')]=50;}
const a=[],b=[];
for(const role of ROLES){const pool=CHAMPIONS.filter(c=>c.role===role);let pair;for(const c of pool){const other=pool.find(d=>d.id!==c.id&&d.type===c.type&&JSON.stringify(d.tags)===JSON.stringify(c.tags));if(other){pair=[c,other];break;}}if(!pair)throw Error(role);a.push(pair[0].id);b.push(pair[1].id);}
const m={id:'controlled-1',a:'nva',b:'crn',bestOf:3,scoreA:0,scoreB:0,sets:[],label:'CONTROL',draft:{picksA:a,picksB:b,bans:[],actions:[]}};
const specs=[['equal',()=>{}],...ROLES.map((r,j)=>[r+'_all20',g=>starters(g)[j].stats.fill(90)]),['team_all10',g=>starters(g).forEach(p=>p.stats.fill(80))],['TOP_LNE20',g=>starters(g)[0].stats[0]=90],['ADC_TF20',g=>starters(g)[3].stats[1]=90],['SUP_VIS20',g=>starters(g)[4].stats[3]=90]];
const N=6000,results=[];
for(const [name,change] of specs){const g=structuredClone(base);change(g);let wins=0,laneWins=0,powers;for(let seed=0;seed<N;seed++){g.seed=seed;const s=simulateSet(g,m);wins+=s.winner===m.a;laneWins+=s.events[0].winner===m.a;powers=s.powersA.map((p,i)=>p-s.powersB[i]);}results.push({name,n:N,wins,setWinPct:Math.round(wins/N*10000)/100,topLaneWinPct:Math.round(laneWins/N*10000)/100,powerDelta:powers.map(x=>Math.round(x*100)/100)});console.log(JSON.stringify(results.at(-1)));}
writeFileSync('balance-results.json',JSON.stringify({method:'6000 paired seeds, same compositions by tags/type, no mastery/meta/form/burn differences, all base stats70, isolated no progression sets',draft:m.draft,results},null,2));

```
