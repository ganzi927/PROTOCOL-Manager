# PROTOCOL Manager — 조합 승률·메타·AI 밴픽 확장 기획

작성: 2026-09-09 / 상태: 구현용 설계안, 아직 게임 코드에 적용하지 않음.
기준: 사용자 수정본의 140챔피언, mastery 배열(Lv0~4), 직접 밴픽·스왑, 시드 기반 경기 엔진.
함께 읽을 문서: `PROTOCOL-Ability-Review.md`. 선수 능력의 경기 영향 개선을 대체하지 않고 함께 진행한다.

## 1. 게임의 핵심 약속

감독은 단순히 승률이 높은 챔피언 다섯 개를 모으는 사람이 아니다. 선수의 챔피언 풀과 상대 전술을 보고, 지금 유효한 조합을 선택하고 훈련하며, 상대의 대응에 맞춰 다시 바꾸는 사람이다.

**챔피언 성능과 상성 → 조합의 유리함 → 선수의 수행 능력 → 경기 중 자원과 교전 → 결과·통계 → 상대의 대응과 새 메타 발견**을 하나의 경영 루프로 만든다.

새 설계의 원칙:
- 조합이 좋아도 선수가 수행하지 못하면 약해진다.
- 좋은 선수가 자기 주력 챔피언으로 불리한 조합을 극복할 수 있다.
- 승률이 높다는 관측 자체가 추가 버프를 주지는 않는다.
- 중계·조합 예상·실제 결과가 같은 규칙과 사건을 설명한다.
- 승률은 조건부 예상치이며 확정 결과가 아니다.

## 2. 참고 사이트에서 확인한 것과 확인하지 못한 것

왓챔 드래프트 페이지의 읽을 수 있는 화면에서 조합/매치업 통계, 파트너 궁합, AI 선픽 추천, 픽률·밴율·최소 판 수와 조합 승률 표시를 확인했다. 게임에는 이처럼 선택 중인 픽에 맞춰 추천과 궁합 정보를 보여주는 경험을 반영한다.

실제 선택에 따른 현재 승률값, 예측 모델 내부 계산식, 데이터 사용 범위 및 공개 연동 API는 확인하지 못했다. 따라서 본 문서의 수치·가중치·사례는 왓챔 수치의 복제물이 아니다. 사이트의 데이터를 자동 수집하거나 이미 연동했다고 전제하지 않는다.

참고: https://whatchamp.lol/page/draft (2026-09-09 열람; 검색 도구가 반환한 페이지 텍스트 기준).

## 3. 승률은 세 가지로 나누어 표시

| 표시 | 의미 | 사용 |
|---|---|---|
| 관측 승률 | 특정 패치/등급/역할/출처에서 실제로 집계된 승패 | 통계 화면. 판 수와 조건을 함께 표시 |
| 조합 기준 예상 | 양 팀 선수 실력·숙련·컨디션을 같은 기준으로 맞춘 조합 간 예측 | 조합 자체의 유불리 설명 |
| 우리 팀 예상 | 실제 출전 선수·숙련·피로·호흡·전술까지 반영한 예측 | 감독의 최종 의사결정 |

미완료 드래프트는 상대의 남은 픽이 정해지지 않았으므로 예측 범위/변동 가능성을 보여준다. 미드가 아직 비어 있는데 완성 조합과 같은 정밀도의 57.38%를 표시하지 않는다.

예시(모두 가상 수치): 조합 기준55%, 우리 팀 예상49%. 설명은 “상성은 좋지만 원딜의 숙련 부족과 피로로 이점을 살리기 어렵습니다.” 반대로 조합 기준48%, 우리 팀 예상56%도 가능해야 한다.

## 4. 조합 평가는 다섯 층으로 계산

### 4.1 챔피언·역할·패치 성능
캐릭터 ID는 유지하고 버전별 프로필을 추가한다. 현재 engage/peel/poke/scale 태그만으로는 역할 차이가 거칠기 때문에 라인 압박, 사거리, 지속딜/순간딜, 진입, 보호, 내구, 웨이브 처리, 성장 곡선, 수행 난도를 게임용 수치로 표현한다.

모든 특성이 최상인 챔피언을 만들지 않는다. 고사거리·높은 압박을 가지면 기동성/안정성 등에서 약점이 있게 한다. 프로필 값은 검증된 실데이터가 없는 부분에서는 명확히 게임 설계값이다.

### 4.2 아군 궁합
바텀 듀오, 미드-정글, 상체 진입, 딜러 보호처럼 함께 플레이할 때 늘어나는 효과다. 같은 편으로 등장한 승률에서 각 챔피언이 원래 강한 정도를 제외한 추가 효과를 추정해야 한다.

예를 들어 게임용 징크스-룰루 프로필은 후반 지속딜과 보호가 맞물리게 설계할 수 있다. 단, 이 때문에 초반 라인도 자동으로 강해지지 않는다. 공식 궁합 순위나 실제 승률을 주장하는 예시가 아니다.

### 4.3 상대 매치업
같은 라인의 직접 상성뿐 아니라 포킹 대 진입, 다이브 대 보호, 짧은 사거리 대 카이팅 등 전 팀을 대상으로 하는 대응을 본다. ‘카운터 챔피언이 있다’만으로 모든 시점에 보너스를 주지 않는다. 실제 진입로, 시야, 성장 시점이 조건을 충족할 때 효과를 낸다.

### 4.4 전체 조합의 완성도
앞선, 보호, 웨이브 처리, 피해 유형, 오브젝트 접근, 성장 시점과 승리 계획을 본다. 조합의 모든 쌍을 독립 보너스로 더하면 10쌍 보너스가 과도하게 쌓이므로 역할별 평균/상한을 사용한다. 아군 궁합에서 설명한 보호 효과를 전체 조합에서 다시 같은 강도로 더하지 않는다.

### 4.5 선수의 수행 능력
챔피언 숙련 Lv0~4, 역할 적합, 선수의 해당 능력, 팀 호흡·전술로 위 효과를 얼마나 실현하는지 계산한다. 난도가 높은 조합은 높은 숙련·메커닉·팀 호흡이 필요하다. 단순 조합은 전력이 낮은 팀도 안정적으로 수행할 수 있다.

기본 선수 능력과 챔피언 효과는 독립 항목으로 남긴다. 선수 OVR 전체를 조합 점수로 치환하지 않는다. 기존 능력 분석에서 드러난 라인전·시야의 약한 승리 연결을 자원·교전 상태로 보완한다.

## 5. 통계 데이터를 쓰는 방법

### 사용할 데이터의 계약
각 통계에는 `source`, `patchId`, `queue`, `region`, `rankBand`, `role`, `sampleSize`, `wins`, `collectedAt`을 붙인다. 챔피언 단독, 아군 페어, 상대 매치업은 별도 테이블이다. 버전과 역할이 다른 표본을 무조건 합치지 않는다.

외부 데이터가 확보되면 허용된 API/파일로 버전별 JSON/CSV 스냅샷을 가져와 검증한다. 첫 구현은 수동 임포트도 가능하다. 키·수집 작업을 경기 POST마다 실행하지 않는다. 외부 연동이 없으면 게임 내 시뮬레이션/설계 프로필을 사용하고 실제 랭크 데이터라고 표시하지 않는다.

### 단순 승률 합산은 사용하지 않는다
52% 챔피언 다섯 개를 뽑았다고 +10%p가 되는 것은 아니다. 사용 선수 실력, 인기 빌드, 숙련자 비율, 상대 조합 등이 섞여 있다. 단독 효과·궁합·상성을 한 모델에서 분리하거나 조건을 맞춘 비교가 필요하다.

초기 표본 완화의 예:
`완화 승률 = (wins + k × 기준확률) / (n + k)`.
기준확률은 조건을 맞춘 기준 모델의 값이다. 정보가 전혀 없으면50%로 시작할 수 있다. k는 검증으로 정할 가상 표본 수다. 이것만으로 선수 실력이나 선택 편향까지 제거되지는 않는다.

페어 효과는 ‘둘이 같이 나왔을 때의 결과’와 ‘각 챔피언 단독 성능으로 예상한 결과’의 잔차로 추정한다. 상대 효과도 같은 방식으로 분리하고 희소한 페어는0에 가깝게 축소한다. 샘플이 부족한 완성10챔피언 조합의 직접 승률에 의존하지 않는다.

예측 모델을 만들 때는 시간순 패치 홀드아웃과 같은 경기가 양쪽 표본으로 중복 유입되지 않는 분리를 적용한다. 강팀이 쓰는 픽의 승률이 높은 현상을 챔피언의 강함으로 그대로 학습하지 않도록 팀/선수 실력 조건을 반영한다.

## 6. 경기 엔진에 연결하는 단일 경로

**조합이 게임 사건의 확률·성과를 바꾸고, 예상 승률은 그 엔진의 결과를 예측하도록 한다.** 조합55%라는 수치를 구한 뒤 모든 교전 확률에5%p를 더하고 마지막 승부에도 다시55%를 적용하면 같은 이점을 반복 계산하게 된다.

권장 구조:
1. 고정한 패치 프로필, 양 팀 픽·역할, 숙련을 평가해 `DraftEffects`를 만든다.
2. 효과는 lane/jungle/objective/teamfight와 성장 시점으로 나눈다.
3. 경기 상태에서 조건을 만족하는 효과만 해당 사건에 적용한다.
4. 사건 결과로 개인 자원·생존·구조물 상태를 갱신한다.
5. 다음 사건은 갱신한 상태를 사용한다. 넥서스 파괴 등 명시한 종료 조건으로 승자를 결정한다.
6. 동일 엔진의 여러 독립 예측 시드 또는 그 엔진에 맞춰 검증한 근사 모델로 예상 승률을 표시한다.

외부 관측 승률은 프로필/효과를 보정하는 근거로 쓰고, 엔진 예상과 외부 관측을 별도 표기한다. 이벤트 엔진에서 이미 보호·사거리·성장 특성을 구현했다면 통계 모델에서는 그 설명을 제외한 잔차만 보정한다.

### 초기 보정 범위와 단위
빠른 연결 단계에서는 단독 패치효과·궁합·매치업을 **구간 파워 점수** 단위로 묶어 구간별 총합±3 같은 보수적 상한에서 시작할 수 있다. 이는 게임용 임시 튜닝 가설이며 승률±3%p라는 뜻이 아니다. 반복 시뮬레이션으로 실제 승률 변화를 측정해 범위를 정한다.

기존 `isMeta ? +2`는 새 규칙팩에서 제거한다. 패치 성능과 궁합으로 이미 설명된 유리함을 ‘메타 배지’ 때문에 추가로 증폭하지 않는다. 이전 저장/경기는 기존 규칙으로 재생 가능하게 버전을 보존한다.

## 7. 메타가 자연스럽게 나타나는 구조

### 원인과 관측을 분리
메타의 원인은 패치 프로필, 조합·상성, 선수 풀, 대회 환경, 상대의 대응이다. 승률/픽률/밴율은 이 현상을 관측하는 지표다. ‘승률이 올라갔으니 다음 주 능력치도 증가’라는 자동 규칙을 두지 않는다.

### 게임 안의 주간 흐름
1. 새 패치 적용: 일부 프로필의 강점/약점과 환경을 소폭 조정한다.
2. 초반 탐색: 팀마다 자기 선수 풀과 전술에 맞는 조합을 시험한다.
3. 대회 결과 축적: 승률·픽률·밴율과 수행 기여가 기록된다.
4. 대응: 상대 AI가 자주 등장하는 핵심 픽을 밴하거나 카운터 조합을 준비한다.
5. 숙련 투자: 감독이 다음 주 특훈과 선수 기용을 바꾼다.
6. 새로운 해법: 비주류 조합이 특정 유행 조합을 상대로 성공하면서 평가가 바뀐다.

이를 통해 능력치 버프 없이도 ‘강하지만 밴이 많은 픽’, ‘승률은 좋아도 우리 선수는 못 쓰는 픽’, ‘유행 조합 저격용 픽’이 나뉜다.

### 통계 표시와 표본 부족
국내10팀 리그만으로140챔피언의 안정적인 통계를 만들기 어렵다. 아래 출처를 구분한다.
- 대회 실제 기록: 해당 커리어의 공식 매치 결과. 적은 표본은 그대로 표시한다.
- 분석가 예상: 오프라인에서 만든 동일 조건 시뮬레이션/균형 모델. 공식 경기 판 수에 합치지 않는다.
- 외부 랭크 통계: 확보한 출처·패치가 있을 때만 별도 표시한다.

메타 화면에는 ‘주류’, ‘밴 우선’, ‘숨은 선택지’, ‘특정 상대 대응’, ‘표본 부족’을 표시한다. 높은 승률과 낮은 표본만으로 숨은 강자로 확정하지 않는다.

## 8. 패치와 장기 커리어

현실 패치를 기준으로 시작할 수 있어도 미래의 게임 연도는 자체 패치가 필요하다. 권장 기본값은 새 스플릿에 큰 패치, 정규시즌 중 사전 공지된 작은 패치다. 플레이오프/국제대회 중에는 고정한다. 구체적 주기는 검증 후 확정한다.

`patchId`는 게임 날짜에 따라 정하고 세트/시리즈 진행 도중 바꾸지 않는다. 데이터 업데이트나 실제 날짜 변화 때문에 저장된 경기 결과가 바뀌지 않게 한다. 과거 패치 스냅샷과 엔진 버전을 함께 보관한다.

선수 숙련은 패치가 바뀌어도 유지한다. 주력 픽이 약해지면 신규 특훈, 선수 기용, 트레이드의 선택이 생긴다. 패치가 바뀔 때 자동으로 최강 챔피언을 숙련하도록 해 주지 않는다.

## 9. AI 팀의 밴픽

### 공통 평가
AI도 사용자와 같은 조합/선수 평가 함수를 쓴다. 합법 후보를 만들고, 자기 선수 풀·남은 역할·조합 완성도·상대 대응을 평가한다. flex/포지션 스왑을 고려하므로 아직 배정되지 않은 픽을 특정 선수에게 성급하게 고정하지 않는다.

픽 평가의 설계식:
`기대 경기 가치 = 현재 픽 이후 남은 합법 선택을 고려한 예상 결과 − 수행 불안정성 + 팀 전술 선호 + 제한된 탐색`.

같은 능력/숙련/조합을 수동 보너스로 또 더하지 않는다. 근사 평가와 최종 예측 중 어디서 각 효과를 반영하는지 명시한다.

### 밴은 상대 선택지를 얼마나 줄이는지 평가
상대의 최고 챔피언 하나를 단순히 밴하는 대신 그 픽이 빠졌을 때 다음 대안까지 고려한다. 상대 원딜이 한 챔피언만 잘하면 저격 밴의 가치가 높고, 대안이 많으면 우리 조합의 카운터를 지우는 편이 낫다.

예: 상대가 보호형 후반 원딜 조합을 자주 사용한다면 핵심 보호 픽 밴, 바텀 압박 조합, 분산 운영 중 자기 선수들이 수행 가능한 해법을 고른다. 이는 설계 예시이며 특정 실존 조합의 승률 주장과 다르다.

### 팀 개성
팀마다 초반 압박/후반 운영/시그니처 중시/상대 저격 성향을 둔다. 열세 팀은 변동성이 큰 합법 조합을 선택할 수 있고 강팀은 안정성을 선호할 수 있다. 성향 차이는 성능 계산의 부정행위가 아니라 후보 선택 취향이다.

### 계산 비용과 공정성
140개 후보×전체 조합 완전 탐색은 요청마다 실행하지 않는다. 가벼운 점수로 후보를 추린 뒤 상위 후보만 얕게 비교하고 서버에서 캐시한다. 예측용 시드는 실제 경기 결과 시드와 분리하고 실제 미래 결과를 알고 고르지 않는다. 사용자의 아직 선택하지 않은 픽은 추정 분포로만 다룬다.

초기 탐색 횟수/후보 수는 성능 측정 후 정한다. 64회 시뮬레이션 승률을 소수점 단위의 확신으로 표시하지 않는다. 작은 승률 차이의 정렬은 더 많은 오프라인 표본이나 보정된 근사 모델을 사용한다. 분석가는 표본·정보·판단 오차를 개선하고 선수 능력을 몰래 올리지 않는다.

## 10. 감독의 게임 화면

### 밴픽 카드
챔피언 사진/이름/가능 역할, 배정 예상 선수, 숙련도, 메타 상태, 자기 조합과의 궁합, 상대에 대한 장단점, 추천 이유를 표시한다. 밴 차례에는 상대의 숙련/대안 관점을 보여준다.

추천은 항상 한 가지가 아니어야 한다. ‘우리 선수에게 편한 픽’, ‘조합을 완성하는 픽’, ‘상대를 저격하는 픽’을 비교할 수 있게 한다.

### 조합 분석 패널
현재 두 팀 픽, 초반/중반/후반 성향, 진입·보호·피해유형·웨이브 처리, 주요 시너지와 약점, 예상 승률과 신뢰도를 보여준다. ‘다음 픽에서 앞선을 보강할 수 있습니다’처럼 행동 가능한 설명을 준다.

우리 팀 예상55%, 조합 기준58% 같은 숫자는 원인 설명과 함께 표시한다. 차이를 선수·숙련·전술별 정확한%p로 분해하려면 실제 반사실 계산이 필요하다. 계산하지 않은 합계 맞추기 숫자는 만들지 않는다.

### 훈련·스카우팅
특훈 목표에 ‘다음 상대 대응’, ‘팀에 없는 보호 픽’, ‘다음 패치 적응’을 추천한다. 기존 미등록 챔피언 특훈의 목표 불일치 문제를 먼저 고친다. 선수 영입 화면은 OVR뿐 아니라 우리 조합에 부족한 챔피언 풀을 보여준다.

### 중계와 리캡
사례: 실제 징크스/룰루가 출전했고 보호·생존 사건이 발생한 경우, “룰루의 보호로 징크스가 살아남아 공격을 이어갑니다”라고 해설한다. 단순히 둘이 픽됐다는 이유로 성공을 선언하지 않는다.

리캡에는 조합의 승리 계획이 수행됐는지, 어떤 선수의 성장/시야/보호가 이를 가능하게 했는지, 다음 세트에서 밴/전술/선수를 어떻게 바꿀 수 있는지 표시한다.

## 11. 생동감 있는 한 시즌의 예시

다음은 시스템이 만들 게임 내 가상 시나리오다.
- 1주차: 보호형 후반 조합이 상위권 팀에서 성공한다. 분석 화면에는 아직 표본이 적다고 나온다.
- 2주차: 여러 팀이 채택하며 픽률과 밴율이 오른다. 우리 선수는 해당 원딜 숙련이 낮아 그대로 따라 하면 불리하다.
- 감독 선택: 기존 주력 바텀 압박 조합으로 대응하면서 후보 선수에게 후반 원딜 특훈을 준다.
- 3주차: AI 상대가 우리 압박 픽을 밴한다. 준비한 두 번째 조합을 꺼내야 한다.
- 스플릿 후반: 같은 조합도 상대가 바뀌면 추천과 성공률이 달라진다. OVR가 높은 선수만 모으는 것보다 넓은 챔피언 풀과 수행 가능한 조합이 중요해진다.

메타 변화가 뉴스, 상대 분석, 밴픽, 훈련, 선수 영입과 경기 해설에 모두 영향을 미친다.

## 12. 개발자가 구현할 데이터/모듈 계약

권장 신규 모듈(아직 없는 파일):
- `lib/balance/types.ts`: 통계 스냅샷·패치 프로필·DraftEffects·예측 타입.
- `lib/balance/evaluate.ts`: 양 팀 픽/역할/프로필을 구간별 효과로 변환.
- `lib/balance/predict.ts`: 미완성 선택의 예측 및 캐시 키.
- `lib/balance/ai.ts`: 후보 축소, 상대 대응, 선택지 제거 가치.
- `lib/simulation/events.ts`: 선수 상태/자원/생존/구조물을 갱신하는 사건.
- `data/balance/<patchId>.json`: 검증된 변경 불가능 스냅샷.

스냅샷은 `datasetId/patchId/source/conditions/sampleSize/collectedAt/modelVersion`을 포함한다. 캐시 키는 패치·모델·선수 능력/숙련·피로/호흡·픽/역할·전술·밴 상태를 포함한다. 팀/상대가 바뀌었는데 과거 예측을 그대로 보여주지 않는다.

저장 구조는 기존 사용자 v3를 명시적으로 변환한다. 버전 숫자만 같고 mastery 모양이 다른 과거 ChatGPT 실험본을 호환으로 취급하지 않는다. 완료한 결과를 새 모델로 재계산하지 않는다. 표시 통계·예측은 클라이언트가 최종 확정할 수 없으며 게임 상태 변경은 기존 서버 명령을 거친다.

## 13. 단계별 개발 순서와 수락 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 0 | 기준 보존·측정 | 기존140챔피언/스왑/숙련 보존, 능력 민감도 결과 기록, 특훈 목표 오류 해결 |
| 1 | 선수 사건·자원 | 라인전/시야가 자원·피습·후속 교전에 영향을 줌. 중계/골드/POG 근거 일치 |
| 2 | 조합 프로필 | 같은 선수 조건에서 조합만 바꾸면 해당 구간에서 변화. 중복 보정 없음 |
| 3 | 예상·추천 UI | 같은 평가를 이용해 우리 선수 수행력과 조합 기준을 구분. 미완성/표본 부족 표현 |
| 4 | AI 대응 | 상대 핵심픽 제거·카운터·조합 완성·flex를 고려. 미래 사용자 픽/결과 시드 미열람 |
| 5 | 메타·패치 | 결과 통계가 나타나고 팀들이 대응. 단순 승률 상승→능력 버프 없음 |
| 6 | 외부 데이터 보정 | 합법적으로 확보한 스냅샷·역할/패치/표본 확인, 미래 경기 홀드아웃으로 보정 검증 |

단계2의 효과 모델/화면 설계는 단계1과 준비를 함께 할 수 있다. 하지만 선수 능력 연결을 끝내지 않은 채 강한 조합 보정만 출시하지 않는다. 외부 데이터가 없어도 단계0~5는 게임 자체 규칙으로 구현 가능하다.

### 구체적인 테스트
- 팀 A/B를 바꾸면 양측 예상 확률이 대칭이어야 한다(사이드 이점이 있으면 그 상태도 함께 교환).
- 동등 조건의 장기 평균이 중립에 가깝다. 좋은 선수를 넣었는데 조합 점수에 가려 기본능력이 사실상 무효화되지 않는다.
- 같은 상대·패치에서 보호형 후반 조합의 초반/후반 특성이 구분된다. 특정 챔피언 궁합의 실제 강약 목표는 데이터/설계로 별도 명시한다.
- 메타 배지 표시를 켜고 꺼도 경기 계산은 동일하다.
- 표본0/새챔피언/희소페어/외부 장애에서 예측이 폭주하지 않는다.
- 패치 전후 저장 재개와 과거 경기 결과가 유지된다.
- AI와 사용자 모두 같은 합법성·평가 규칙을 사용한다.
- 예측과 실제 결과는 많은 경기에 대해 보정도를 검사한다. ‘60%로 예측한 한 경기를 졌다’는 오류 판정이 아니다.
- 게임 통계를 다음 버프의 직접 입력으로 사용해 자기강화가 발생하지 않는지 확인한다.

## 14. Claude에 전달하는 실행 지시

이 파일을 `docs/claude/PROTOCOL-Composition-Meta-Design.md`에 두고, `PROTOCOL-Ability-Review.md`와 함께 읽게 한다.

```text
두 분석·설계 문서와 현재 소스를 읽고 사용자140챔피언/Lv4숙련/직접밴픽/스왑 버전을 기준으로 구현해줘.
목표는 선수 능력·조합·상성·메타가 사건과 자원에 영향을 주고 그 결과가 통계와 AI 대응으로 이어지는 게임이다.
먼저 단계0을 확인하고, 선수 사건·자원 연결과 조합 효과 모델을 작은 단위로 구현해줘.
왓챔 화면의 실제 승률값·내부 API를 확보했다고 가정하지 마. 데이터가 없으면 게임용 초기값과 출처를 명시해줘.
관측 승률, 조합 기준 예상, 우리 팀 예상은 구분하고 isMeta+2를 새로운 조합효과와 중복 적용하지 마.
게임 승자는 사건 엔진에서만 결정하고 예측 화면은 그 엔진과 일치하도록 검증해줘.
각 작업 후 실제 테스트 결과와 다음 할 일을 HANDOFF/BACKLOG/DECISIONS에 갱신해줘.
```

```markdown

- 선수의 사건·자원 기여를 유지하면서 조합 효과·예측·AI 대응·메타 통계를 단계적으로 구현한다.
- 실데이터 미확보 항목을 실제 승률로 표현하지 않고 메타 배지의 중복 버프를 피한다.
```
